# Design Agent build benchmarks

Generated by `node agents/design/benchmark.mjs --write`. 20 sites (4 verticals x SMB and Micro x 2-3 profiles), fictional data from `fixtures.mjs`.
Machine: Apple M1, 8 cores, 16 GB, Node v22.23.1, Astro build (static output, CSS inlined). No LLM call, so no token cost.

**Target (System 04 section 1): about 10 s per site. Result: 1.30 s worst case sequential, 1.22 s average. About 8x inside the target.**

## Sequential (one build at a time)
| | time |
|---|---|
| First build of the run | 1.25 s |
| Warm mean / p50 / p95 / max (n=19) | 1.22 s / 1.21 s / 1.30 s / 1.30 s |
| of which Astro build (mean) | 1.19 s |
| of which CSS inlining (mean) | 0.03 s |
| All 20 sites | 24.42 s |

## Parallel (each build in its own work root, so Astro's mutable state does not collide)
| Workers | Wall time for 20 sites | Per site (wall / n) | Single build under load (mean / p95) |
|---|---|---|---|
| 2 | 14.14 s | 0.71 s | 1.41 s / 1.45 s |
| 4 | 10.81 s | 0.54 s | 2.15 s / 2.25 s |
| 8 | 10.41 s | 0.52 s | 3.75 s / 4.61 s |

Sequential baseline for the same set: 24.42 s (1.22 s per site).

## QA (deterministic checks, no browser)
Render plus schema, build, placeholder, required-content, link and contrast checks for one site: 1.26 s. Lighthouse and layout checks need Chrome and a local port; they run on Tyler's machine (not measurable in this sandbox).

## Findings
- Rendering is dominated by Astro's build (~97% of the time); resolving the design and inlining CSS are negligible.
- Parallel builds work because each build gets a private root (`.work-<slug>/`) and a private Vite cache. Sharing one root fails with an Astro data-store write race.
- Throughput flattens after 4 workers on this machine (2: 14.14 s, 4: 10.81 s, 8: 10.41 s); default to 4, since more workers only slow each individual build.
- The spec's per-site target is met with wide margin even sequentially, so parallelism matters for batch runs (nightly demo generation), not for a single demo.
