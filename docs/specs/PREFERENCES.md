- [stated] "Show me [docs]" means: present as clickable file links Tyler can open, NOT prose descriptions
- [stated] When presenting files, use interactive links (not summaries or tables of contents)
- [stated] Save this interpretation to universal memory for future BuildFlow sessions

## Documentation Structure Philosophy

- [stated] All system files follow three mandatory sections: (1) What is this file for? (2) What is in it? (3) The specs
- [stated] Goal: least amount of files that accurately depict different parts of the business
- [stated] Files are build specs for agents to implement — every file must be agent-actionable
- [stated] Archiving is preferred to deletion; archive empty files only after consolidating their content elsewhere
- [stated] Each file should integrate seamlessly so agents can read scope -> understand implementation -> execute
